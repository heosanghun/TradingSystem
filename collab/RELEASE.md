# 공개 저장소 정리 기준 (12-01 심사 공개용)

- 총괄: CC (T-005). 각 에이전트는 자기 소유 경로를 이 기준에 맞춘다(AG: T-107, CX: T-208).
- 시점: 수치 동결(11-25) 직후 정리, 11-28까지 공개본 확정.

## 원칙

정리는 **불필요한 것과 근거 없는 것을 빼는 일**입니다. 결과를 숨기거나 바꾸는 일이 아닙니다.

- 공개본의 모든 수치는 공개본 안의 코드·설정·로그로 다시 확인할 수 있어야 한다.
- 논문 서술과 구현이 다른 곳은 감추지 않고 README의 "논문과의 차이" 절에 적는다.
- 실행하지 않은 것을 실행한 것처럼, 근사를 정확 구현처럼 쓰지 않는다.

## 공개 방식 (D-8 결정 필요)

작업 저장소의 이력에는 내부 조율 문서와 중간 상태가 남아 있습니다. 권장안은 다음과 같습니다.

1. 지금의 작업 저장소는 비공개로 돌린다(사용자가 GitHub 설정에서 직접).
2. 수치 동결 뒤 정리된 트리를 새 공개 저장소(또는 태그 `v1.0-defense`의 스냅샷)로 낸다.
3. 공개본에는 동결 시점의 실행 로그와 대장을 포함한다.

## 이 저장소 밖의 위험 (D-9, 사용자만 조치 가능)

같은 GitHub 계정의 공개 저장소에 다음이 있습니다. 심사위원이 계정을 보면 함께 보게 됩니다.

- `2_ESWARegime`: `paper_alignment`(행동 반전, B&H 혼합, 1.76배, 1.89 상한) 설정과 관련 문서
- `1_Multimodal-Trading-System`: 난수로 만든 성과 그래프 스크립트, 익일 가격 참조 코드
- `mcts-financial-world-model`: `calibrate_to_thesis` 옵션
- `HyperGraphTrading`: 그래디언트가 끊긴 증류 코드

이 저장소들을 어떻게 할지(고정 해제, 보관 처리, 비공개, 설명 추가)는 지도교수와 상의해 정하십시오. 특히 이미 투고·게재된 논문의 수치가 그 보정 계층에서 나온 것이라면 저장소 정리로 해결되는 문제가 아니므로 별도로 다뤄야 합니다.
