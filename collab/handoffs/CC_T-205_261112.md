# T-205 로컬 LLM 서빙과 처리 속도 실측

- 상태: 검토 요청
- 환경: RTX 5090 Laptop 24GB, Ollama 0.40.16, `deepseek-r1:32b`(DeepSeek-R1-Distill-Qwen-32B, 4비트, 19GB)
- 주의: 측정 내내 다른 Python 프로세스가 GPU를 함께 쓰고 있었다(보드의 장시간 실행 표에는 기록 없음). 단독 사용 시에는 더 빠를 수 있다.

## 설정에 관한 발견 (그대로 두면 실행이 안 됨)

1. **컨텍스트 길이.** Ollama 기본값 32,768이면 모델이 28GB를 차지해 20%가 CPU로 넘어가고 초당 2.6~4.8토큰이 된다. `num_ctx=4096`이면 20GB로 전부 GPU에 올라간다(VRAM 20.9GB). 프롬프트 입력은 최대 725토큰이었으므로 4,096으로 충분하다.
2. **사고 토큰.** `think=False`를 줘도 이 모델은 사고를 한다. 엣지 검증에서 약 450토큰, 토론 분석가 프롬프트에서는 2,500토큰을 넘겨도 답변이 나오지 않았다(95초 이상, 답변 없음).
3. **사고 건너뛰기.** 마지막에 `{"role": "assistant", "content": "<think>\n\n</think>\n\n"}`를 붙여 응답을 이어 쓰게 하면 사고 없이 JSON이 바로 나온다. 이때 `num_predict=256`이 논문의 "라운드당 최대 256토큰 JSON"과 같은 의미가 된다.
4. **출력 포장.** 답변이 ```` ```json ... ``` ```` 코드 블록으로 감싸여 나온다. 현재 `extract_json_object`의 정규식으로 처리된다.

## 측정값 (사고 건너뛰기, num_ctx 4096, num_predict 256)

| 항목 | 값 |
|---|---|
| 엣지 검증 호출당 | 평균 4.23초, 중앙값 4.29초, 95% 4.60초 (n=30), 출력 평균 60토큰 |
| 엣지 검증 파싱 실패 | 0 / 30 |
| 토론 호출당 | 평균 8.11초, 중앙값 7.91초, 95% 11.28초 (n=128), 출력 평균 165토큰 |
| 토론 호출 중 256토큰에서 잘린 것 | 6 / 128 (JSON 미완 → 파싱 실패) |
| 인용 검증 기각 | 116 / 122 (95%) |
| 봉당 호출 수 | 평균 12.8 (기각 재시도 때문) |
| 봉당 시간 | 평균 104초 |
| 모델 적재 | 최초 30초, 이후 2.4초 |

## 문제 두 가지 (CX에 요청)

1. **인용 형식 불일치로 정상 답변이 거의 전부 기각된다.** 모델은 실제 엣지 ID와 TE 값을 맞게 인용하지만 `E02 (SPY -> BTCUSDT, TE: 0.4537)`처럼 쓴다. 검증기는 `[Edge ID: #E02, TE: 0.4537]`만 인식한다. 지금 상태로 본 실행을 하면 "환각 기각률"이 95%로 나오는데, 이것은 환각이 아니라 형식 문제다. 프롬프트에 형식 예시를 넣고, 검증기는 대괄호 없이 쓴 `E숫자`와 인접한 `TE:` 값도 읽어 존재 여부와 수치를 대조하도록 넓혀야 한다. 기각 사유를 "형식 누락"과 "존재하지 않는 ID·틀린 수치"로 나눠 집계해야 표 6.15의 환각 기각률이 의미를 가진다.
2. **뉴스 맥락이 없으면 엣지 검증자가 30건 모두 REJECT했다.** 실제 뉴스 두 줄을 넣은 시험 호출은 ACCEPT(신뢰도 0.85)였다. 본 실행에는 T-202의 뉴스를 반드시 넣어야 하고, 승인율을 metrics에 기록해야 한다. 승인된 엣지가 없는 날의 처리(공통 팩터 엣지만 남음)도 확인이 필요하다.

## 전체 실행 시간 추정

호출당 토론 8초, 검증 4.2초 기준. 인용 형식 문제가 고쳐져 봉당 2~6회 호출이라고 가정.

| 구성 | 계산 | 시간 |
|---|---|---|
| 토론, 전 봉(2020-10 ~ 2023-12, 약 28,500봉) | 28,500 × 2~6회 × 8초 | 5.3 ~ 15.8일 |
| 반사실 토론, 시험 구간 전 봉(19,727봉) | 19,727 × 2회 × 8초 | 3.7일 |
| 엣지 검증, 주간 캐시(잡음 입력에서 하루 524개 후보) | 170주 × 524개 이상 × 4.2초 | 4.3일 이상 |
| **합계(논문 설정 그대로)** | | **약 13 ~ 24일** |

마감(수치 동결 11-25)까지 불가능하다. 축소안:

| 구성 | 계산 | 시간 |
|---|---|---|
| 토론을 4시간마다(사이 봉은 직전 신호 유지), 약 7,100봉 | 7,100 × 3회 × 8초 | 2.0일 |
| 반사실 토론을 시험 구간에서 균등 추출한 2,000봉 | 2,000 × 2회 × 8초 | 0.4일 |
| 엣지 검증을 주별 TE 상위 50개로 제한 | 170주 × 50 × 4.2초 | 0.4일 |
| **합계** | | **약 3일** |

## 논문에 영향
- 표 6.14의 교사 지연 "평균 3,500ms": 토론 1회는 최소 2회 호출이라 16초 이상이다. 실측값으로 바뀐다(T-004에서 구간별로 측정).
- 제IV장·부록 A.3: 사고 건너뛰기 설정, 컨텍스트 4,096, 토론 주기·검증 상한을 쓰면 그대로 서술해야 한다.

## 확인하지 못한 것
- GPU 단독 사용 시의 속도.
- 인용 형식을 고친 뒤의 실제 봉당 호출 수와 진짜 환각 비율.
- vLLM 등 다른 서버에서의 배치 처리 속도(Windows에서는 설치가 까다로워 시도하지 않음).
