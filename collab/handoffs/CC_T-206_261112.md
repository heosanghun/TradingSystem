# T-206 호가창 데이터 표본 검증

- 상태: 검토 요청 (CX가 독립 확인하면 좋음. 네트워크가 없으면 생략)
- 담당 변경: CX 샌드박스에 네트워크가 없어 CC가 수행

## 한 것
- Tardis.dev 무료 표본(매월 1일) 중 2022-05-01 바이낸스 현물 BTCUSDT의 `book_snapshot_25`(45.9MB)와 `trades`(13.4MB)를 받아 `data/cache/tardis_sample/`에 두었다. git에는 올리지 않는다.
- `LOBWindowProcessor.compute_40_lob_features`에 상위 10호가와 구간별 체결량·방향을 넣어 `(40, 100)` 윈도우를 만들었다.

## 측정값 (2022-05-01 하루)
| 항목 | 값 |
|---|---|
| 스냅샷 수 | 762,983 |
| 체결 수 | 1,021,151 |
| 스냅샷 간격 | 중앙값 100.0ms, 평균 113.2ms, 95% 200ms, 99% 301ms |
| 시간당 스냅샷 | 중앙값 31,938 |
| 100틱 윈도우 길이 | 중앙값 10.9초 (5% 10.1초, 95% 13.8초) |
| 40특징 행렬 | NaN 0, 첫 윈도우에 상수 열 0 |
| 봉당 10개 윈도우, 결정 시점 윈도우 | 정상 생성, 모두 유한값 |
| 하루 용량(압축) | 59.3MB → 2020-10 ~ 2023-12 1,187일이면 약 70GB |

논문의 "100틱은 평상시 약 10초 분량"과 일치한다. 코드 쪽 40특징 구성은 실제 데이터로 동작한다.

## 확인하지 못한 것
- 전 기간 자료의 가격. 유료 구독이 필요하고 결제는 사용자만 할 수 있다(D-1).
- 2020~2021 구간의 스냅샷 품질. 거래소 목록 API로는 바이낸스 현물이 2019-03-30부터 제공된다는 것만 확인했다.
- 체결을 스냅샷 구간에 묶는 방식(직전 스냅샷 이후 ~ 해당 스냅샷 시각)은 검증용으로 내가 정한 것이다. 본 구현 때 `src/ts/data`에 넣고 테스트해야 한다.

## D-1 결정에 쓸 사실
- 구매하면 논문 서술(100ms 스냅샷, 100틱 약 10초, 상위 10호가)을 그대로 구현할 수 있다. 디스크는 충분하다(여유 267GB, 필요 약 70GB. 봉당 윈도우만 추출하고 원본을 지우면 훨씬 적다).
- 무료로 받을 수 있는 것은 매월 1일 하루씩, 평가·학습 구간 통틀어 39일치뿐이다. 전 구간 평가에는 쓸 수 없다.
- 구매하지 않으면 1분 봉 대용 특징으로 가야 하고 제V장 3.1절과 표 5.1을 고쳐야 한다.
