## 바꾼 것
- src/ts/study2/llm_client.py: 전송·응답구조·JSON 오류를 최대 3회 지수 백오프로 재시도. 실패는 LLMCallError. 미완 think 블록은 답변으로 채택하지 않음.
- use_cache=False로 읽기와 쓰기 모두 우회. llm.use_cache=False 범위는 기존 토론 엔진 전체 호출을 우회시키며 finally로 복원.
- 캐시 키에 서버 주소·생성 설정 포함. 실패 답변은 캐시하지 않음.
- src/ts/study2/persistent_state.py: SQLite 원자적 봉 체크포인트와 주간 엣지 캐시.
- scripts/run_study2.py: 입력/코드 해시별 네임스페이스, 일별 그래프 스냅샷 복원, 봉 단위 재개. 실패 봉은 failed로 기록하고 다음 봉 진행. 끝에 실패가 있으면 metrics를 incomplete로 저장하고 불완전 교사 배열은 내보내지 않음.
- 진단 축소 주기는 --diagnostic-run에서만 허용, 기본은 전 봉. 반사실 주기와 실제 모드 기록. 진단 출력은 별도 하위 폴더이며 대장에 기록하지 않음.
- 뉴스/연구1 입력 누락 시 중립·균등 신호로 대체하지 않고 오류. 연구2와 비교 모델 스크립트에 RunContext 연결.
- scripts/run_baselines_and_eval.py: 수렴 예산 합의 전 reduced_training_budget=True로 잠정 대장만 사용.
## 검증
- mock HTTP 응답으로 타임아웃 → 깨진 JSON → 성공, 캐시 읽기, 캐시 완전 우회, 영구 실패 집계 확인.
- 봉 처리 중 실패 후 다음 봉 처리, SQLite 재개와 연속 실행의 레코드 일치 확인.
- 연구2 실행 스크립트를 중간 KeyboardInterrupt로 끊고 재개: 교사 배열·합의문·인용 지표가 중단 없는 실행과 일치.
- 로컬 TCP 소켓이 금지돼 실제 모의 HTTP 서버 대신 requests.post 응답 대역 사용. 실제 네트워크 서버 장애 테스트는 미확인.
## 미확인과 한계
- 모델 서버의 생각 토큰·답변 토큰 분리, 실제 256 JSON 답변 토큰 보장, 실 LLM 실패율은 미확인. T-205 담당 CC에게 인계함. 현재 max_tokens=256은 기존 서버 요청 한도이며 사고 포함 여부를 코드만으로 보장하지 않음.
- metrics.llm_telemetry는 현재 프로세스 요청 통계. 재개 전 프로세스까지 합친 누적 호출 수가 아님. 봉별 인용 통계와 실패 레코드는 영속 저장됨.
- 실패 봉은 재시작만으로 자동 재시도하지 않음. 기록을 유지해 미완을 드러냄. 원인을 해결한 뒤 실패 키를 명시 삭제하거나 새 네임스페이스로 실행해야 함.
- AG에게 연구3에서 metrics.status/설정 검증 후 교사 파일을 읽도록 요청. 이전 실행 잔여 파일 사용 방지 필요.
